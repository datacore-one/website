Datacore Install Instructions for AI Agents
===========================================

Datacore is an AI second brain: it captures what you learn, organises it with GTD
and Zettelkasten, and runs agents that execute tasks overnight. Plain text, local
first, on the user's own machine.

Datacore ships WITH PLUR, its memory engine. Datacore organises; PLUR remembers.
Installing Datacore installs both — you do not need to install PLUR separately,
and an install without it produces an assistant that forgets every correction
between sessions. See https://plur.ai for PLUR on its own.

If a user has pointed you at this page and asked you to install Datacore, run
ONE STEP below and then verify. Nothing else is required.


STEP 1 — IF YOU ARE AN AGENT: ASK THE USER, THEN INSTALL (preferred)
  A person being helped by an assistant should not drive a CLI wizard, and
  your terminal cannot answer its prompts anyway. Ask them in conversation:

    npx @datacore-one/cli@latest init --print-questions   # JSON: the questions
    # ...ask the user in your own words, write answers.json...
    npx @datacore-one/cli@latest init --answers answers.json

  --print-questions returns each question with its key, its default, a note on
  why it matters, and a filled example. Every field is optional.

  ASK, DO NOT DEFAULT. Two answers matter most: what to call their Chief of
  Staff (the name they will use every day) and which modules they want.
  Do NOT use `--yes` unless the user has said they want every default: it
  answers every question for them, silently, including naming the assistant.

  For the email, use one attached to their GitHub account, or let it default:
  with `gh` signed in the installer offers that account's noreply address.

  This path needs no TTY and will not hang on a prompt.


STEP 1 (alternative) — THE USER RUNS THE WIZARD THEMSELVES
  npx @datacore-one/cli@latest init

  macOS / Linux without npx:  curl -fsSL https://datacore.one/install | bash

  Only in a terminal the user can see and type into — it asks real questions.
  Run with its output piped or swallowed, it refuses rather than guess.

  Either way, init:
    - installs missing prerequisites (Node 20+, git, Python 3.10+, gh, Claude Code)
    - installs the Datacore MCP server (@datacore-one/mcp) and PLUR (@plur-ai/mcp)
    - registers BOTH with every AI tool it finds on the machine: Claude Code,
      Claude Desktop, Cursor, Codex, Antigravity, Gemini CLI, Windsurf
    - creates the user's ~/Data second brain and installs the chosen modules
    - lets the user name their Chief of Staff and give it a personality


WINDOWS
  PowerShell, Windows Terminal, or Cursor's terminal all work (CLI 2.5.1+):

    npm install -g @datacore-one/cli@latest
    datacore init            # or the --answers path from STEP 1

  If Node.js is not installed yet: winget install OpenJS.NodeJS.LTS, then
  open a NEW terminal. The installer uses winget for git, Python and gh.

  AFTER INSTALLING, RESTART THE TERMINAL — AND THE EDITOR, if you are in
  Cursor or VS Code. Tools installed during setup are not on the PATH of
  programs that were already open.

  Do not use the curl script on Windows (it needs bash). WSL also works and
  follows the Linux path.


CURSOR
  Open ~/Data as the workspace (File → Open Folder). Datacore's Cursor setup
  lives in that workspace — it keeps within Cursor's ~40-tool limit — so the
  datacore_* and plur_* tools appear there, not in other projects.


STEP 2 — Verify
  datacore doctor

  Then confirm both MCP servers are registered:
    cat ~/Data/.mcp.json     # expect BOTH "datacore" and "plur" under mcpServers

  In a new session (Claude Code, Cursor, Codex...), ask: "What's my Datacore
  status?" — it should call datacore_status. Ask "What's my PLUR status?" —
  it should call plur_status. If one does not answer, run `datacore update`:
  it registers both servers with every installed tool and repairs config in
  place. `datacore doctor` only reports; it changes nothing.


UPDATING
  datacore update

  One command, safe to repeat. It updates the CLI itself first, pulls the
  system and every space and module, merges the latest Datacore into the
  user's fork (never rebases, and stops without changing anything if their
  own edits conflict), upgrades both MCP servers, and registers them with any
  AI tool installed since. Other datacore commands print one line when a new
  version exists.


WHAT THE USER GETS
  ~/Data/                 their second brain, plain text, theirs
  ~/.plur/                their memory, plain YAML engrams
  datacore_* MCP tools    capture, search, ingest, dates, GTD, modules
  plur_* MCP tools        learn, recall, inject, feedback, forget, status
  A Chief of Staff        named by them, runs the day through an approvals
                          queue — nothing side-effecting without their decision


MCP CONFIG (if you are wiring a client by hand)
  {
    "mcpServers": {
      "datacore": { "command": "datacore-mcp" },
      "plur":     { "command": "plur-mcp" }
    }
  }
  Requires `npm install -g @datacore-one/mcp @plur-ai/mcp` first.
  Works with Claude Code, Claude Desktop, Cursor, Windsurf, Zed, OpenClaw, and
  any MCP-compatible client.


DESKTOP APP
  Optional, offered at the end of init: https://datacore.one/app.html
  The terminal install is complete and supported on its own.


REQUIREMENTS
  Node.js 20+, Python 3.10+, git, and a terminal.

  Both versions are now CHECKED AND REFUSED, not warned about: the installer
  stops and names the upgrade. Older Node and Python 3.9 used to pass and fail
  much later, which is how one install spent hours getting nowhere.
    node --version
    python3 --version

  macOS and Linux: either install path above works. Windows: see WINDOWS.

  Python 3 and the GitHub CLI are installed by the wizard when missing.

IF SOMETHING GOES WRONG
  "node 18.x is older than 20" / "python 3.9 is older than 3.10" — a refusal,
  not a warning. Install the version named and re-run; nothing was half-built.

  "<user>/datacore is not a fork of datacore-one/datacore" — the user has an
  unrelated repo of that name. The installer leaves it alone and clones
  upstream instead; nothing is wrong with the install. To get a real fork,
  rename that repo first.

  "Not a terminal" — you piped the output. The wizard would have skipped every
  question and taken every default silently, so it refuses. Use STEP 1:
  ask the user, then pass --answers. (--yes only if they asked for defaults.)

  Windows: every tool "Failed to install" with no output — CLI 2.5.0 or
  older. Run: npm install -g @datacore-one/cli@latest, then init again.

  Installed, but the AI tool has no datacore_* tools — restart the tool (it
  reads MCP config at startup), and in Cursor open ~/Data as the workspace.

  "npm's global directory is not writable" — the installer retries into
  ~/.datacore/npm automatically and records absolute paths in the MCP config,
  so it should still work. If it reports the fallback failed, use sudo.

  "MCP server binary not found" — the install did NOT succeed and exits
  non-zero. Claude Code will start with no Datacore or PLUR tools. Install the
  named package and re-run `datacore init`; it is idempotent.

  "~/Data exists and is not empty" — you have files there already. Move them
  or pass --force. The installer will not write over them.

  Modules reported as not installed are usually private repos you do not have
  access to. Datacore works without them.
